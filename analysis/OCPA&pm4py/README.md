# CSQ4: Resource and Supplier Participation and Cross-Object Interactions

This directory supports the case-study question:

> How are Resources and Suppliers distributed across the process, and where do shared actors interact with multiple business objects?

PM4Py derives Resource participation and Supplier quotation metrics from the preserved OCEL 2.0 log. OCPA-derived tables describe actor-linked cross-object interactions. The figure script combines the two result workbooks into four thesis figures. Existing script, worksheet, and figure names retain the earlier **BQ4** identifier; they refer to **CSQ4** in the thesis.

Restore the workbook as described below before generating all four figures.

## Run from Git Bash

From the repository root, enter this directory and install the analysis and plotting dependencies:

```bash
cd 'analysis/OCPA&pm4py'
python -m pip install pm4py pandas numpy matplotlib openpyxl
```

### 1. Regenerate PM4Py results

```bash
python script/bq4_pm4py_analysis.py \
  --input data/intangible_asset_ocel2_run1.jsonocel \
  --out output
```

This command generates ten CSV tables, the PM4Py workbook, and metadata. Resource CSV files and `supplier_dependency.csv` are regenerated by this command even when only their Excel worksheets are retained in the checkout.

The optional `--export-ocdfg` flag adds OC-DFG frequency and performance overview images and requires Graphviz for rendering.

### 2. Restore the archived OCPA workbook

Run the following in Git Bash to recover the figure input from its preserved repository revision:

```bash
mkdir -p output/OCPA
git show '17d0278970e10f93bf7761bddaacb969b0166c2c:analysis/OCPA&pm4py/output/OCPA/BQ4_OCPA_results.xlsx' \
  > output/OCPA/BQ4_OCPA_results.xlsx
```

This restores the existing OCPA results used by the hotspot figure. Re-executing the OCPA analysis requires the archived converter and analysis scripts and a compatible OCPA environment. The current two-script workflow regenerates PM4Py results and figures from the preserved OCPA workbook; it does not rerun OCPA.

### 3. Generate the four figures

```bash
python script/generate_bq4_figures_from_excel.py \
  --pm4py output/tables/BQ4_PM4Py_results.xlsx \
  --ocpa output/OCPA/BQ4_OCPA_results.xlsx \
  --out output/figures
```

Each figure is exported as a **300 dpi PNG**, an SVG with editable text, and a vector PDF. Use `--dpi 600` to increase PNG resolution. Figure regeneration from existing workbooks requires `pandas`, `numpy`, `matplotlib`, and `openpyxl`; OCPA installation is only needed when rerunning the archived OCPA analysis.

## Metric definitions

### Resource participation

| Metric | Definition |
| --- | --- |
| Event-based workload | Number of unique events associated with each Resource, counting each Resource-event pair once |
| `workload_share` | Resource event count divided by the sum of event counts across all Resources |
| Resource-activity participation | Unique event count for each Resource-activity combination |
| Business-object coverage | Unique objects associated with a Resource through shared events, divided by the total number of objects of that type |
| Temporal distribution | Monthly and weekly Resource-event counts |

Workload measures logged participation frequency. Processing time and capacity utilisation require additional duration and availability data. The coverage scope comprises `Requirement`, `Asset`, `Order`, `Invoice`, `AcceptanceRecord`, and `Voucher`; `Project` is retained as process context.

### Supplier participation and selection

Let `Q` be the number of unique **Obtain Quotations** events in the log. For each Supplier, the script calculates:

| Field | Event definition or formula |
| --- | --- |
| `participation_count` | Unique **Obtain Quotations** events with a Supplier relation qualified as `queried supplier` |
| `selection_count` | Unique **Evaluate And Select Quotation** events with a Supplier relation qualified as `selected supplier` |
| `total_quotation_procedures` | `Q`, shared by all Suppliers |
| `participation_rate` | `participation_count / Q` |
| `selection_rate` | `selection_count / Q` |
| `selection_share` | `selection_count / sum(selection_count)` across Suppliers |
| `selection_given_participation` | `selection_count / participation_count`; undefined when participation is zero |
| `count_consistent` | Whether `selection_count <= participation_count` |

The Supplier comparison figure uses **`participation_rate` and `selection_rate` from `Supplier_Rates`**, with the same quotation-procedure denominator. Several Suppliers can participate in one quotation procedure, so participation rates can sum to more than 100%.

`selection_share` describes the distribution of all selections and supplies the concentration calculation. The conditional metric `selection_given_participation` describes selection among a Supplier's own participations. These fields have distinct denominators and are retained separately.

Supplier selection is recorded at **Evaluate And Select Quotation**. A later contract rejection can end the process before **Create Purchase Order**, so selection counts and created-order counts can differ. Supplier links to downstream events represent associations with the process and its business objects; execution roles are identified separately through Resource relations.

### Supplier concentration and Order coverage

Using Supplier selection shares `s_i`:

```text
HHI = sum(s_i ** 2)
effective_supplier_count = 1 / HHI
top1_selection_share = max(s_i)
```

`supplier_dependency` measures the fraction of unique Order objects associated with each Supplier through shared events. Its denominator is the total number of Order objects.

The concentration export uses the field name `total_selected_orders`. In the current script, this field contains the **total Supplier selection count**; actual Order counts are recorded by the dependency analysis.

### OCPA cross-object interaction breadth

The archived OCPA analysis treats `Resource` and `Supplier` as actors and uses the same six business-object types listed above. A cross-object actor-event observation associates an actor with at least **two different business-object types** in one event.

The `07_activity_hotspots` worksheet provides:

- `multi_object_events`: distinct qualifying event IDs for each activity, displayed as `n` in the figure;
- `mean_object_type_breadth`: mean number of business-object types across qualifying actor-event observations;
- additional actor, maximum-breadth, and business-object-count summaries.

The hotspot figure reads these stored values directly. It ranks activities by mean breadth, then qualifying event count, both descending.

The preserved baseline contains **506 events**, **186 objects**, and **2,403 event-object relations**. It includes **30 quotation procedures**, **30 selections**, and **29 Create Purchase Order events**.

| S2 | 12 | 5 | 40.0% | 16.7% |

| S4 | 18 | 5 | 60.0% | 16.7% |
| S5 | 12 | 6 | 40.0% | 20.0% |
| S6 | 6 | 3 | 20.0% | 10.0% |

For this baseline, `HHI = 0.177778`, effective Supplier count is `5.625`, and the largest selection share is `23.33%`. The heatmap has 18 nonzero Resource-activity combinations.

Metadata records the input's byte-level SHA-256 and software versions used for the PM4Py run. The stored input path identifies the generation environment; the runnable input path for this directory is given in step 1. Windows line-ending conversion can change the byte-level hash, so regenerate metadata when analysing the current working-copy file.

Reproduction here starts from the preserved simulation log. The original stochastic CPN run seeds were not retained; the documented commands reproduce downstream analyses and figures from that log.
